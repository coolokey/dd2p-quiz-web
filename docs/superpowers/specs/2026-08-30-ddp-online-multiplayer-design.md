# DDP 網路雙人對戰設計規格

## 目標

在既有「玩家 VS 電腦」與「本機雙人對戰」之外，新增第三個「網路雙人對戰」模式。兩位玩家可分別使用電腦或行動載具連線答題並同步觀看戰鬥結果；同一班級可以同時有多組獨立對戰。

## 不變的既有契約

- 題庫、科目分類、角色、四個校園場地、戰鬥傷害規則、音效與暫停流程不變。
- 鍵盤、行動載具觸控按鈕與 USB 手把均維持可作答。網路模式中每一位玩家使用自己裝置上的任一既有輸入方式。
- 直式行動載具提示、返回首頁、重新開始與更換題庫等既有保護機制保留。
- 本機雙人仍使用 `left`／`right` 雙方控制；網路模式的單一瀏覽器只控制自己的玩家，不會把第二支手把誤視為遠端玩家。

## 使用者流程

1. 起始畫面新增「網路雙人對戰　03」。尚未設定即時服務時顯示「網路對戰尚未啟用」及原因，不影響前兩種模式。
2. 主持人建立班級大廳，選擇題庫、場地、回合設定、玩家名稱方式與配對方式，取得一組六位英數房間碼與 QR 連結。
3. 學生輸入房間碼或掃 QR 後，以三種方式之一取得暫存顯示名稱：自行輸入暱稱、從主持人名單選擇、系統編號。
4. 班級大廳同時提供三種配對：學生自行選對手、主持人指定兩位學生、系統自動兩兩配對。每一組建立自己的二人戰鬥房。
5. 雙方預載場景和角色圖後按「準備完成」。兩人都準備完成才由服務端寫入開始時間並進入第一題。
6. 每一回合只同步必要事件：題組識別碼、亂數種子、題號、開始時間、玩家首次作答、裁定結果、生命值與回合狀態。問題內容仍由已發布的題庫載入。
7. 結束、重開、返回大廳與斷線都會通知同房對手；房間於結束後 10 分鐘自動清除，未開始房間於 30 分鐘自動清除。

## 即時服務與資料邊界

- 遊戲前端繼續由 GitHub Pages 提供。
- 第一版使用 Firebase Realtime Database 免費方案作為即時資料通道。它只保存暫時的班級大廳、配對與戰鬥事件，沒有帳號、Email、長期成績或學生個資。
- Firebase Web 設定值雖會公開於前端，但必須搭配限制房間路徑、格式、逾時與只允許本人席位寫入的 Realtime Database Rules；不得把管理金鑰放入 GitHub。
- 第一版的公平性範圍是「以 Firebase transaction 的第一筆成功寫入裁定搶答權」。由於題目資料已公開提供給瀏覽器，本版不是防作弊競賽平台；若未來需要正式考試防作弊，應另建受信任後端與登入機制。
- Firebase 免費方案的同時連線與傳輸有上限，因此 UI 需呈現服務未啟用、連線失敗與滿載訊息，並在 Firebase 控制台設定用量提醒。

## 資料模型

```
rooms/{roomCode}
  settings: { quizId, sceneId, battleSettings, pairingMode, nameMode, hostPlayerId }
  lobby: { status, createdAt, expiresAt }
  players/{playerId}: { displayName, rosterId?, role, status, connectedAt }
  pairings/{matchId}: { leftPlayerId, rightPlayerId, state }
  matches/{matchId}
    config: { quizId, sceneId, characterIds, questionSeed, battleSettings }
    state: { phase, questionIndex, startAt, hp, scores, winner, updatedAt }
    answers/{questionIndex}: { claimedBy, answerIndex, claimedAt, resolution }
```

- `roomCode` 使用不易混淆的六位英數字元，發生碰撞時重新產生。
- `playerId` 與 `resumeToken` 是每次加入時產生的隨機值；`resumeToken` 只存於該裝置的 `sessionStorage`，有效期限內可回到原席位，不可寫入其他玩家可讀取的房間資料。
- 一場 `match` 僅有兩個玩家；班級大廳可有多個 `match`。
- 題目順序以共享亂數種子與題組識別碼重建，答案選項位置沿用目前「隨機且平均」邏輯。

## 連線、斷線與公平性

- 在兩端資源載入與準備完成前不可開始倒數。
- 作答事件以 Firebase transaction 原子取得該題的 `claimedBy`。失敗者立刻收到已被搶答的同步狀態，不能覆蓋第一筆。
- 現有「答對攻擊、答錯交由對手」規則保持。服務端事件決定同房兩端動畫與下一題的順序。
- 連線中斷時顯示「正在等待重新連線」，保留 45 秒。重新連線後由共享狀態補齊目前題目和生命值；逾時則結束該組並回大廳。
- 主持人可終止尚未開始的配對；進行中的雙方任一人退出時，另一人收到已結束訊息並可回大廳。

## 介面

- 起始畫面：第三個模式按鈕與連線服務狀態。
- 主持人頁：選擇設定、建立房間、房間碼、QR、玩家等待名單、三種配對操作與結束班級活動。
- 加入頁：輸入房間碼、名稱模式對應輸入、連線與錯誤提示。
- 對戰頁：沿用現有戰鬥畫面，增加極小的網路狀態提示與「返回班級大廳」功能，不遮蔽答題區。

## 驗收條件

1. 原有 `solo`／`local` 模式及全部測試維持通過。
2. 未配置 Firebase 時，遊戲仍可正常載入並清楚停用網路模式。
3. 兩個獨立瀏覽器可建立、加入、配對、準備、同步答題、同步動畫、完成與回大廳。
4. 至少三組同時房間不共享題號、生命值、答案或角色。
5. 三種配對與三種名稱模式都各有測試覆蓋。
6. 斷線後 45 秒內重新載入可回到原本對戰；逾時則正確結束。
7. 鍵盤、觸控與 USB 手把在網路模式的單一玩家端仍可觸發四個答案；本機雙人手把映射測試不回歸。

## 不在第一版範圍

- 線上排行榜、帳號登入、長期成績、語音／文字聊天室、觀戰、跨校大型賽事與防作弊考試。
- 把 Firebase 管理憑證、教師個資或學生真實姓名放進前端或 GitHub。
