# 行動載具限定橫式全螢幕設計

## 目標

僅在手機與平板進入對戰時嘗試全螢幕與鎖定橫式；桌機與觸控螢幕筆電維持一般瀏覽器視窗，不受全螢幕或螢幕方向鎖定影響。

## 裝置判斷

- 判定行動載具：Android、iPhone、iPad、iPod；以及以 `MacIntel` 回報、但具有多點觸控的 iPadOS 裝置。
- 判定桌機：其餘裝置，包括具觸控功能的 Windows／ChromeOS／macOS 筆電與桌上型電腦。
- 不以 `maxTouchPoints` 單獨判定，避免將觸控螢幕筆電誤判為平板。

## 對戰流程

- 行動載具進入對戰時：保留既有全螢幕請求、橫式鎖定、直向暫停遮罩與離場解鎖流程。
- 桌機進入對戰時：仍註冊 resize、背景暫停與可見性事件，但不呼叫 `requestFullscreen()`、`screen.orientation.lock()` 或 `screen.orientation.unlock()`；不因直向視窗而顯示行動裝置的旋轉遮罩。
- 鍵盤、USB 手把、行動觸控按鈕、暫停、音效、CPU 與題庫規則均不變。

## 驗收

- 桌機假瀏覽器進入與離開對戰時，全螢幕、方向鎖定與解鎖呼叫次數均為零。
- 手機與 iPadOS 假瀏覽器仍各執行一次全螢幕與橫式鎖定；離場時執行一次解鎖。
- 既有方向、背景暫停與輸入保護測試均通過。
