# DDP 知識對決：依觸控能力顯示作答按鈕

日期：2026-08-26

## 目標

只有具備觸控能力的手機、平板與觸控筆電，在橫向對戰時顯示畫面上的 `1`、`2`、`3`、`4` 作答按鈕；沒有觸控能力的桌上型電腦與一般筆電不顯示這些按鈕。

## 已核准規則

- 以瀏覽器回報的觸控點數判定裝置是否具備觸控能力，不以螢幕尺寸或裝置名稱猜測。
- 觸控筆電視為觸控裝置，因此顯示作答按鈕。
- 沒有觸控能力的電腦隱藏作答按鈕，且不保留觸控按鈕所需的左右或下方空間。
- 原有鍵盤作答在所有裝置上都持續有效。
- 觸控按鈕仍只在橫向對戰顯示；直向對戰沿用旋轉提示遮罩。

## 技術設計

在 `mobile-controls.mjs` 增加純函式判定 `navigator.maxTouchPoints` 與舊版 Microsoft 的 `msMaxTouchPoints`。應用程式啟動時將判定結果同步成根元素的 `touch-capable` 類別。所有觸控按鈕顯示、戰區留白及矮橫式壓縮規則均以該類別為必要條件，避免非觸控電腦套用行動版版面。

## 驗收標準

- `maxTouchPoints > 0` 時，根元素具有 `touch-capable`。
- `maxTouchPoints = 0` 或未提供時，根元素不具有 `touch-capable`。
- 非觸控電腦的下方或側邊答案按鈕保持隱藏，戰區不套用觸控留白。
- 觸控手機、平板與觸控筆電在橫向時顯示答案按鈕。
- 既有鍵盤測試、觸控輸入測試與完整測試套件全部通過。
