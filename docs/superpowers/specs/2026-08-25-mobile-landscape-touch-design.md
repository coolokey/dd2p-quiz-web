# DDP 知識對決：行動載具橫式觸控設計

日期：2026-08-25

## 目標

讓現有網頁遊戲可在手機與平板上完整遊玩，同時保留桌面鍵盤操作、玩家對 CPU、本機雙人、題庫、音效及對戰動畫。對戰階段以橫式畫面為必要條件，確保題目、人物、血量與觸控按鈕都有足夠空間。

## 已核准決策

- 行動版同時支援「玩家 VS 電腦」與「本機雙人對戰」。
- 首頁、題庫、規則、戰場與選角可以直向或橫向操作。
- 按下開始對戰後，嘗試進入全螢幕並鎖定橫向。
- 瀏覽器無法鎖定方向時，以直向遮罩阻擋對戰；轉成橫向後才開放作答。
- 本機雙人採左右側邊按鈕：紅方固定在左側，藍方固定在右側。
- 玩家對 CPU 採底部一排四個大型答案按鈕。
- 現有鍵盤操作持續有效，可與觸控操作共存。

## 範圍

### 本次包含

- 行動裝置方向偵測、全螢幕請求及橫向鎖定嘗試。
- 直向阻擋畫面、返回主選單入口與橫向恢復。
- 單人及本機雙人的觸控答案按鈕。
- 可作答方提示、動畫期間鎖定及答錯換手提示。
- 旋轉、頁面失焦及休眠後回到遊戲的狀態保護。
- 行動版響應式排版、觸控尺寸、安全區及誤觸防護。
- 對應的單元測試、整合測試及瀏覽器畫面驗證。

### 本次不包含

- 網路連線對戰。
- 帳號、房號、排行榜或戰績儲存。
- 將網站改造成必須安裝的原生 App。
- 改寫現有題庫、計分、攻擊傷害或 CPU 難度規則。

## 操作與畫面

### 玩家 VS 電腦

- 對戰場景、人物、血量與題目維持中央主要視覺。
- 畫面底部顯示 1 至 4 的大型答案按鈕，數量依當題選項數調整。
- 每個按鈕同時顯示選項編號；題目文字仍保留在原本的選項區，避免長答案塞進控制鍵。
- 按鈕使用紅隊識別色，最小可觸尺寸為 48 CSS px，目標尺寸為 56 CSS px。

### 本機雙人

- 紅方答案按鈕垂直排列於畫面左側，藍方答案按鈕垂直排列於畫面右側。
- 每側依當題選項數顯示 2 至 4 個按鈕，編號與中央答案一致。
- 目前可作答的一側提高亮度並發光；不可作答的一側降低透明度且不接受輸入。
- 任一方答錯後，中央狀態清楚顯示「紅方答錯，換藍方作答」或相反文字。
- 兩側控制區不得覆蓋人物、血量、題目圖片及答案內容。

### 直向阻擋

- 對戰中偵測到直向時，顯示覆蓋整個視窗的旋轉提示。
- 提示包含旋轉圖示、「請將裝置轉成橫向」、恢復說明及「返回主選單」。
- 遮罩顯示時不可透過觸控或鍵盤提交答案。
- 遮罩層需包含瀏海、圓角與底部手勢區的 safe-area padding。

### 橫向恢復

- 回到橫向後移除遮罩，顯示原本題目、分數、血量與剩餘時間。
- 不重新建立賽局、不重新洗牌、不重播開場，也不重複送出旋轉前的答案。
- 若旋轉發生於已提交答案的動畫期間，該次答案允許安全完成結算；橫向恢復後呈現已結算的最新狀態。

## 技術架構

### 觸控輸入控制器

新增獨立的行動輸入元件，職責為：

- 依模式、玩家與選項數建立觸控按鈕。
- 將觸控輸入轉成現有 `{ player, answerIndex }` 格式。
- 呼叫與鍵盤相同的 `processAnswer` 路徑，不複製題目判定、計分或動畫邏輯。
- 依 `battleInputGate`、可作答玩家、方向暫停及動畫狀態更新按鈕啟用狀態。
- 使用單一 pointer 事件提交答案並消除後續合成 click，確保一次觸碰只提交一次。

鍵盤與觸控只負責產生相同的答案意圖，真正的合法性仍由既有 lifecycle 與 game state 判定。

### 方向與全螢幕控制器

新增獨立方向控制器，職責為：

- 在使用者按下開始對戰的手勢中請求全螢幕。
- 全螢幕成功後嘗試 `screen.orientation.lock('landscape')`。
- 以 viewport 寬高與 orientation 事件判斷目前是否為直向，不能只依賴方向鎖定 API 成功與否。
- 對戰開始後監聽旋轉、全螢幕變化、頁面可見性及尺寸變化。
- 對戰結束或返回選單時移除監聽並嘗試解除方向鎖定。
- API 不存在、被拒絕或中途離開全螢幕時採安全降級，不中止賽局。

### 暫停協調

方向控制器不直接修改分數或題目，而是通知對戰協調層進入或離開 `orientationPaused` 狀態。

進入直向暫停時：

- 關閉答案輸入。
- 固定限時制剩餘秒數並停止 interval。
- 暫停 CPU 等待計時並保存尚餘毫秒數；恢復時只以該剩餘時間建立一個新 callback，舊 callback 必須失效。
- 若已有合法答案進入動畫，允許該 lifecycle 完成，但禁止排程下一次 CPU 作答。

恢復橫向時：

- 先依最新賽局狀態重新渲染，再重新開放合法輸入。
- 限時制從保存秒數繼續。
- 單人模式只為目前開放題排程一個 CPU callback。
- 舊方向、舊題目與舊 session 的 callback 一律失效。

## 輸入與競速規則

- `pointerdown` 與鍵盤 `keydown` 都進入同一輸入閘門。
- 動畫進行、直向暫停、結果頁及離開對戰時均拒絕新答案。
- 雙方同時觸碰時，沿用既有「先進入合法提交者取得搶答權」規則。
- 答錯後只有另一方按鈕啟用；答錯者繼續觸碰不會改變狀態。
- 按住、滑動離開、同一手指產生的合成事件不得重複提交。
- 控制區使用 `touch-action`、文字不可選取及適當的 pointer capture／取消處理，避免縮放、反白或滑頁干擾搶答。

## 錯誤處理

- 全螢幕或方向鎖定失敗：改以 viewport 方向偵測降級；只有直向時顯示遮罩，不向玩家顯示原始例外訊息。
- 觸控提交 Promise 失敗：釋放輸入鎖、取消過期 CPU callback、重新渲染最新快照，並顯示可理解的短暫提示。
- 頁面從背景恢復：重新檢查方向、全螢幕、目前題目與 CPU 排程，不重複計分。
- 視窗尺寸連續變化：以節流方式更新版面與方向狀態，避免重複暫停／恢復。
- 觸控控制器找不到必要 DOM：不影響鍵盤作答，並在瀏覽器 console 留下包含元件名稱與賽局階段的診斷錯誤。

## 響應式規則

- 對戰版面以 landscape 且 viewport 高度較小為主要條件，不只使用單一寬度斷點。
- 題目圖片限制最大高度，長題幹及長選項允許縮放字級或在題目區內捲動，不讓整頁產生水平捲軸。
- 音量控制在小型橫式手機保留靜音按鈕，其餘滑桿可收合至設定面板。
- 觸控控制區使用 `env(safe-area-inset-*)` 避開瀏海與系統手勢區。
- 桌面寬螢幕不顯示觸控控制器，除非偵測到 coarse pointer；鍵盤提示與既有桌面排版不變。

## 測試與驗收

### 自動化測試

- 觸控按鈕產生正確的玩家與答案索引。
- 2、3、4 選項只產生相同數量的按鈕。
- 單次 pointer 操作只能提交一次。
- 不合法玩家、動畫中、直向及結果頁輸入都被拒絕。
- 答錯換手後只啟用另一方控制器。
- 直向暫停不減少限時秒數，不讓 CPU 作答。
- 橫向恢復只排程一個 CPU，舊 callback 不得作答。
- 全螢幕與方向鎖定 Promise 拒絕時仍可使用橫向遮罩流程。
- 旋轉發生於動畫、正解揭示及結算邊界時，不重複計分或多前進一題。
- 現有鍵盤及 160 項測試持續通過。

### 瀏覽器驗證

- iPhone Safari 尺寸與安全區。
- iPad Safari 尺寸。
- Android Chrome 手機及平板尺寸。
- 玩家 VS CPU、本機雙人、固定題數及限時制。
- 直向進入、橫向恢復、遊戲中途旋轉、離開分頁再返回。
- 快速連按、雙方同時觸碰、動畫期間誤觸、觸控與鍵盤混用。
- 純文字題、含圖片題、長文字題與 2 至 4 選項題。

### 完成標準

- 行動載具可從首頁完成選題、設定、選角並開始遊戲。
- 直向對戰無法作答，橫向後可立即恢復。
- 單人與同機雙人的所有合法觸控按鈕可正確判定答案。
- 觸控不造成雙重提交、重複攻擊或比分錯亂。
- 戰鬥人物、血量、題目、答案與控制器在主要手機及平板橫式尺寸皆可見且不重疊。
- 桌面鍵盤版本功能與畫面不回歸。
