# 行動載具橫式保護與完整戰鬥舞台縮放設計

## 目標

修正部分手機瀏覽器未被識別為行動載具，導致橫式鎖定、全螢幕與直向暫停遮罩全部失效的問題；同時讓手機與平板的橫向對戰畫面以完整舞台等比例縮放。桌機仍不得進入全螢幕，並維持原本的大版面。

## 裝置判斷

- 第一層：保留既有 Android、iPhone、iPad、iPod 與 iPadOS 的瀏覽器識別。
- 第二層：當識別字串未命中時，以多點觸控與短邊螢幕尺寸判定為行動載具。短邊不超過 1024 CSS px 的觸控螢幕視為手機或平板。
- 觸控筆電／桌機因短邊通常超過 1024 CSS px，維持桌機模式；無觸控的桌機永遠維持桌機模式。

## 對戰流程

- 行動載具：維持全螢幕請求、橫式鎖定、直向遮罩、直向暫停與離場解鎖。
- 桌機：不請求全螢幕、不鎖定或解鎖方向、不因直向視窗暫停。
- 行動載具橫向進入對戰後，以包含戰場、角色、血量區、題目、答案、狀態列與觸控作答鍵的單一完整舞台為縮放單位，依實際可用寬高計算一個等比例縮放係數。
- 縮放後的舞台置中顯示於安全區域內；畫面不足時縮小而不裁切，空間足夠時不超過桌機設計尺寸，避免放大造成模糊。
- 直向時不套用縮放舞台，而是維持直向暫停遮罩，要求使用者轉成橫向。
- 不改變角色素材比例、戰鬥規則、鍵盤、USB 手把、觸控作答、音效或暫停選單。

## 版面邊界

- 桌機寬螢幕維持目前全寬戰鬥版面，不加入行動舞台縮放，也不誤判為平板。
- 手機與平板僅在橫向戰鬥狀態啟用等比例縮放；選單與非戰鬥頁面維持既有響應式版面。
- 縮放計算只使用可視 viewport 與安全區域，不能依裝置型號、固定像素尺寸或使用者代理字串決定版面比例。
- 兩側作答鍵需保留可點擊的最小觸控尺寸，且不能蓋住題目、答案或角色。

## 驗收

- Android／iPhone／iPad 與未知識別字串的窄螢幕觸控裝置皆判定為行動載具。
- Windows 觸控筆電與無觸控桌機皆判定為桌機。
- 行動載具的控制器仍會呼叫全螢幕、橫式鎖定與離場解鎖；桌機呼叫次數均為零。
- 在 16：9、20：9 與平板橫向可視範圍中，戰場、完整角色、題目、四個答案與觸控鍵皆同時可見，且彼此維持同一縮放比例。
- 桌機版面不新增黑邊、不縮小、不進入行動裝置的全螢幕或方向保護流程。
- 所有現有測試通過。
